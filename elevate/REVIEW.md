## Adjudications of the builder flags

H1 line count: pre-existing condition in this rendering environment, not a regression. At 1440px the base H1 (74px) also renders on three lines here (height 226px) and the build renders three (235px at 80px). At 390px both render two lines; at 768px the build renders two lines; neither version overflows at any width. The local Chromium does not have the site font stack, so its wider fallback metrics wrap the second clause. The plan checklist line about two lines at 1440px cannot be decided in this environment for either version; it needs one look on a machine with the real font stack before anyone treats it as a defect.

Token spillover: within the plan intent, on all three points. The header docs button is the same .btn component S1.5 redefines; its fill change to deep coral is the component change itself, its inline padding of 10px 18px still wins over the new component padding, and its rendered height is 48px in both versions at 1440px, so nothing shifts. White on the old bright fill failed the floor at 3.89 to 1 everywhere this component appears, so fixing the component everywhere is the craft floor working as intended. The closing panel button keeps its foam fill and ink text (measured background white, color ink) and gains only the S1.5 padding and min-height, which L7 expressly anticipates when it says the S1.5 button values apply there through the shared tokens. The selection and focus values are defined by S1.13 as page level browser surfaces, and L7 anticipates them applying beyond Stage 1. None of the three is an overreach. For completeness, the other scoped items did not spill: features H2 size and color, features tidemark, and all later sections measure at base values.

Plan before values that did not match the mirror: the result still matches plan intent, on both points. Hero padding: the plan before column said the hero inherited 88px; the mirror's rendered hero (.hero-b) actually carried 52px top and 40px bottom. The builder set the after values anyway, and the computed hero padding is exactly 64px and 72px, the outcome the plan specifies. Copy button: the plan before column said no transition and no active state, but the mirror already granted both through a later grouped rule, which is why base and build compute the button identically (160ms strong curve transition, scale 0.97 on press). The builder's added declaration is redundant but harmless, and the S1.12 outcome values are exactly as specified. In both cases the error sits in the plan's before column, not in the built result.

Two pre-existing defects surfaced by the craft floor walk, identical in base and build, neither introduced by this build and neither counted against it above. First, primary button press: under a fine pointer, holding the button down computes transform translateX(-2px), not scale(0.97), because the later gated hover rule overrides the :active rule at equal specificity; measured identically in base and build. The plan declared round 1 press behavior conforming and out of scope, so this is a round 1 cascade conflict the plan's audit missed. Second, reduced motion: the frame computes transform none under prefers-reduced-motion, losing its static -2deg tilt, because the later reduced motion rule for .rvf elements overrides the frame rule; again identical in base. Both deserve a fix or an explicit waiver in a later pass.
