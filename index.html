URL signature

One URL. Every instruction inside it.

Every request is GET /<signature>/<operations>/<source-url>. The first segment is the HMAC-SHA256 of everything after it. Click a segment to see what it does.

https://img.example.com/////

The signature is shortened for display. A real one is 64 hex characters.

Signature. Proof the URL came from you. The server recomputes the HMAC-SHA256 over the operations and source exactly as they appear. A match serves the image; a miss gets a 403.
# Sign the remainder. The hex output is segment one of the URL.
printf '%s' '300x200/https://example.com/photo.jpg' \
  | openssl dgst -sha256 -hmac 'your-secret'
# SHA2-256(stdin)= 3c1f6c180116661877bd4c85fd201a178087d74c1cc188cc584e819d901308c6
// Sign once, reuse the URL everywhere.
import { buildURL, buildSrcSet } from "@crabcrop/url";

const url = buildURL({
  base: "https://img.example.com",
  secret: "your-secret",
  operations: "crop:1200x630:smart/filters:format(webp):quality(80)",
  source: "https://example.com/photo.jpg",
});
# Standard library only. Nothing extra to haul in.
from crabcrop_url import build_url, build_srcset

url = build_url(
    base="https://images.example.com",
    secret="your-secret",
    operations="300x200/filters:grayscale",
    source="https://example.com/photo.jpg",
)
// The same crate the server verifies with.
use crabcrop_url::{build_url, sign};

let signature = sign(secret, "300x200/https://example.com/photo.jpg");
let url = build_url(base, secret,
    "crop:1200x630:smart/filters:format(avif):quality(auto)",
    "https://example.com/photo.jpg")?;

Check the scheme yourself: secret your-secret, remainder 300x200/https://example.com/photo.jpg, HMAC-SHA256 3c1f6c18…08c6. The same test vectors run in every SDK. Full signing guide, key rotation, and expiry rules: the documentation.

Formats supported

Every major format. In and out.

Originals arrive in whatever format they arrive in. Crabcrop takes any of them in and serves the right one back out. Name no format and the visitor's Accept header decides: AVIF first, then JPEG XL, then WebP.

JPEG
DecodeEncode

Universal. quality(auto) is verified perceptually for it.

PNG
DecodeEncode

Lossless, and carries alpha.

WebP
DecodeEncode

Still and animated, both ways. The modern default.

GIF
DecodeEncode

Animation survives: frames, delays, and loop count.

AVIF
DecodeEncode

The smallest files, and the first choice in negotiation.

JPEG XL
DecodeEncode

In and out for everyone, with verified quality(auto).

HEIC / HEIF
DecodeNo encode

What phone cameras shoot, decoded in pure Rust. Goes back out as any output format.

SVG
DecodeRasterizes

Sanitized first, scripts and external references stripped, then rasterized into the pipeline.

Animated sources can also leave as real video: filters:format(mp4) or format(webm), encoded by an external encoder you configure. Details in the format docs.

Major features

Small URL. Long reach.

The transform is only the first tide. Presets, purging, metadata, and AI are built into the same URL.

Presets that stay put

A preset names an operation string on the server, so templates stay short and the menu stays under operator control. Roll changes out under a new name, never edit one in place.

preset:og-card

Purge one, or the group

/purge invalidates every stored variant of one result. /purge-group clears a whole preset output set. Purge signatures use their own subkey, so an image signature can never be replayed as a purge.

POST /purge-group/<signature>/small

Meta and placeholders

Send Accept: application/json and get dimensions, format, and sizes instead of bytes. Add placeholders for the dominant color, palette, a tiny blurred preview, and a ThumbHash string.

Accept: application/json; placeholders=1

URLs that explain themselves

Swap the front of the path for /explain/ and the server reports on the URL instead of serving the image: signature and expiry status, the source, every operation in plain words. It verifies the same signature first.

GET /explain/<signature>/...

Sources where they live

HTTP and HTTPS under a source policy, S3 and S3-compatible stores, Google Cloud Storage, or a local file root that refuses path escapes. Every fetch is bounded, and EXIF orientation is applied at decode.

s3://bucket/key · gs://bucket/key · file:///path

Build from anywhere

TypeScript and Python SDKs, the crabcrop-url Rust crate, an MCP server for coding agents, and Next.js, Nuxt, and Hydrogen loaders. One grammar, one signing scheme, the same test vectors everywhere.

@crabcrop/url · crabcrop_url · crabcrop-url

AI features: models you supply, inference in process

AI filters run ONNX models you provide as files, loaded at boot. No model configured means a clean 501, never a silent fallback. Every after image below is the direct output of a running crabcrop server. Drag the sliders.

AFTERBEFORE

Background removal

removebg keeps the subject and swaps the background for real alpha, ready to composite anywhere.

fit-in:1000x667/filters:removebg:format(webp)

AFTERBEFORE

Studio mode

studio(product) names an outcome: the subject cut out, set on a clean backdrop, a contact shadow under it, margin on every side. The listing shot in one filter.

fit-in:1000x667/filters:studio(product,bg:white,shadow:soft,pad:10)

Smart crop keeps the subject whole

The plain center crop clips Snap's raised claw. :smart finds the subject, and with a face model it keeps faces whole too.

crop:760x760:smart

AFTERBEFORE

Redaction and more

blurclass(person) blurs every detected person and nothing else. The same model family powers face redaction, upscale(2) super-resolution, and meta tags, alt text, moderation verdicts, embeddings, and aesthetic scores.

fit-in:1100x733/filters:blurclass(person)

Studio backdrops resolve on the server: bg:white, any hex, bg:brand for your configured brand color, or bg:none to keep the alpha. Full AI reference: the documentation.
